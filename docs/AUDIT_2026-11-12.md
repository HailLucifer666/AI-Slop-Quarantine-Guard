# Repo Audit — 2026-11-12 (kee audit)

**Scope:** whole repo — api/, web/, tests, workflows, infra, launcher. **Method:** three parallel read-only sweeps (AST symbol sweep over 510 top-level symbols in api/app against a 3,958-file reference corpus; release-readiness table; kee defect-class hunt against the honesty-critical paths) plus owner verification of every headline claim. **Cross-reference:** absorbs `docs/AUDIT_2026-11-11.md` (its two confirmed defects remain open and are re-ranked here; its 19 leads stay triaged there). Findings marked **[11-11]** trace to that audit.

## Codebase map (compact)

FastAPI backend (`api/app`, 49 files, async) + Next.js 15 dashboard (`web/`) + launcher bats. Analyzers are module-level `check_x(diff, repo_context)` functions registered in TWO runner lists (scan.py, worker.py); findings flow through one finalize chain into SQLite via store.py; the PR path publishes GitHub check-runs via github_client.py. Deterministic engine SQG001–007 + SQG009 (SQG008 reserved), no LLM in the decide path. Tests: 524, offline, accuracy corpus with replayed network boundaries.

## History first — the constraints that produced this

Nothing here was a bad decision at the time. Three constraints compounded: (1) **solo-builder speed** — the slop this product detects is the slop fast building produces, so the repo carries its own medicine (dead UI experiments, three hand-synced regexes, a duplicate chain); (2) **honesty-first redesigns mid-flight** — the engine moved from boolean conclusions toward the three-outcome discipline (registries.py did it right; the verdict layer hasn't caught up), leaving seams; (3) **a fix wave sitting unmerged** — six open PRs carry today's RCE fix, false-alarm fixes and honesty docs, so every audit finding below is judged against the FIX TREE, while `main` itself still ships next 15.5.19.

## Release readiness verdict (v0.1.0)

**Blocked by, in order:** (1) the six open PRs — `main` still ships the RCE and the false alarms; (2) QW1 strix (every PR wears a red X); (3) B1/B2 — the verdict layer is the product's headline promise and it still collapses failure into green; (4) Phase 7 artifacts (CHANGELOG, tag, pins, permissions, logging); (5) QW6/QW8 README/SECURITY drift — a honesty product with stale honesty docs fails its own standard. **Solidly ready:** fail-closed boot config, label-only gate behavior, secret hygiene (nothing committed, gitleaks scoped, fork-PR safe), Redis degradation, rate limiting, corpus-backed zero-FP claim, dependabot, lockfile sync, catalog accuracy on spot-checked rules.
