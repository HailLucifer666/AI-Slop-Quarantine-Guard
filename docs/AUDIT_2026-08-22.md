## F1 (Critical) — A one-line `.gitignore` in the scanned repo deletes findings, silently

**Where:** `api/app/ingest.py` — `_collect_dir_ignore_spec()` / `walk_dir()` / `read_zip()`

**What the code does, mechanically.** Before walking a tree, `_collect_dir_ignore_spec`
pools every `.gitignore` and `.dockerignore` found *anywhere in the repository being
scanned* into one non-anchored `pathspec`. `walk_dir` then drops any file matching that
spec with a bare `continue`. The path is not added to `skipped`, and the code says so on
purpose:

```python
if _ignored_by_spec(spec, rel):
    continue  # quietly ignored (project's .gitignore) — not a "skipped" file
```

Those ignore files are attacker-controlled input: they are content of the repository
under examination, authored by whoever is being scanned.

**Why it is not hypothetical.** Proven end-to-end through `run_scan` against a repo
containing a format-valid AWS access key id, with and without a one-line `.gitignore`:

```
--- WITHOUT .gitignore ---
  total_findings=1  SQG002(secrets)=1   skipped list shown to user: []
--- WITH .gitignore hiding credentials.py ---
  total_findings=0  SQG002(secrets)=0   skipped list shown to user: []
```

One line — `credentials.py` — takes a committed AWS key from **reported** to **absent**,
and the user is told nothing was withheld. `files_skipped` stays `0`. In a repo whose
other files satisfy the census, every rule still reports as having run, so the coverage
table — the mechanism specifically built so a gap cannot masquerade as a pass — agrees
that the scan was complete.

**When it bites.** Now, on every whole-repo scan. It needs no sophistication: the single
most common real-world `.gitignore` line, `.env`, already excludes the highest-value
secret file in most repositories from the secret scanner.

**The fix.** Honoring a project's ignore rules for *noise* is right and should stay. What
must change is that suppression becomes visible and disqualifying:

1. Record every ignore-suppressed path in a distinct list (`suppressed_by_repo_ignore`),
   never a bare `continue`.
2. `analytics.clean` and `coverage.fully_covered` must be `False` whenever that list is
   non-empty — the same rule already applied to timed-out and errored rules.
3. Consider restricting repo-supplied patterns to directory-shaped ones, so a repo can
   exclude `build/` but cannot exclude `credentials.py`.

**Scope.** The hardcoded `IGNORE_DIRS` denylist is ours, not the repo's, and is fine as-is.

## F2 (Critical) — `walk_dir` follows symlinks out of the tree and ingests host files

**Where:** `api/app/ingest.py:walk_dir()` — the `open(abs_path, "rb")` read. There is no
symlink check anywhere in `api/app/` (`grep -rn "islink\|realpath\|O_NOFOLLOW" app/` → no
matches).

**What the code does, mechanically.** `os.walk` defaults to `followlinks=False`, which
prunes symlinked *directories* — and that is likely what made this look safe. It does
nothing about symlinked *files*: each one is yielded as an ordinary filename, and
`open()` resolves it. Git stores symlinks as mode `120000` and restores them as real
symlinks on checkout, so `clone_repo()` faithfully reconstructs whatever links the
attacker committed before handing the directory to `walk_dir`.

**Why it is not hypothetical.** Proven:

```
ingested paths: ['main.py', 'notes.txt']
host file content pulled into the scan set: True
content: -----BEGIN RSA PRIVATE KEY-----
```

`notes.txt` was a symlink to a file outside the repository. Its contents entered the
`{path: content}` map, which is the input to every analyzer. The full chain is reachable
from the public API: publish a repo containing `notes.txt -> /root/.ssh/id_rsa` →
`POST /api/scans {"source":"url", ...}` → SQG002 matches the PEM header → the matched
line is stored in `Evidence.snippet` → `finding_to_dict` serializes `evidence.snippet`
→ `GET /api/scans/{id}` returns it to the caller. The deployment target is Linux
(`infra/fly.toml`, `infra/docker-compose.yml`), where symlink checkout is the default.

This host holds `slopguard-lucifergalactus.2026-06-27.private-key.pem`, the `.env`, and
`api/app.db`. The scanner reads the filesystem of the machine that runs it.

**The fix.** In `walk_dir`, skip any entry that is not a regular file within the root:

```python
if os.path.islink(abs_path):
    continue
```

Prefer the containment check — `os.path.realpath(abs_path)` must be under
`os.path.realpath(root)` — because it also covers a symlinked directory reached via a
path that `os.walk` did not prune. `read_zip` is **not** affected: it never extracts, and
a symlink entry's "content" is just the target path string.

**Scope.** `source=local` shares the same `walk_dir` and is fixed by the same change.

## F3 (High, latent) — The 90s analyzer budget cannot fire for SQG002, SQG003 and SQG006

**Where:** `api/app/scan.py:ANALYZER_BUDGET` + `asyncio.wait_for(run(), ...)`, and the
same pattern in `api/app/worker.py:_run_pr_analysis`.

**What the code does, mechanically.** `check_secrets`, `check_sast` and
`check_placeholders` are declared `async def` but contain **zero `await` expressions**
(`grep -n "await " app/analyzers/{secrets,sast,placeholders}.py` → no matches). A
coroutine with no await runs start-to-finish in a single step the first time it is
driven. `asyncio.wait_for` schedules a timeout callback on the event loop, and the event
loop cannot run that callback while a coroutine is executing synchronously. The timeout
fires only at an await point that never comes.

**Proven:**

```
wait_for returned NORMALLY (timeout never fired)
budget=0.5s  actual elapsed=3.00s
heartbeats during the 3s analyzer: 0 (expected ~15 if loop were free)
```

Two guarantees fail together: the budget, and the liveness heartbeat, which is a task on
the same starved loop.

**Honest severity — this is latent, not live.** Measured at the current ingest ceiling
(1500 files / 46.2 MB, just under `MAX_TOTAL_BYTES`): `secrets 12.73s`, `sast 22.54s`,
`placeholders 8.94s`. All are far under both the 90s budget and the 300s lease, so no
scan is failing today. The regexes were also checked for catastrophic backtracking and
are linear — no nested quantifiers, all bounded character classes. **The ingest caps are
what is actually protecting this path; the timeout contributes nothing.** The code
comments credit the timeout, which is why this is worth writing down rather than leaving
to be rediscovered.

**When it bites.** Raise `MAX_TOTAL_BYTES`/`MAX_FILES`, add a slower rule, or run on
slower hardware, and one analyzer crosses 300s of uninterrupted synchronous work. Then
`_heartbeat_loop` never stamps, `reconcile_stale_scans` sees a lapsed lease and marks a
perfectly healthy scan `failed` with "the worker process most likely stopped mid-scan" —
a false statement — and the still-running worker afterwards calls `complete_scan` on that
same row.

**The fix.** Run the synchronous analyzers off the loop: `await asyncio.to_thread(run)`.
The budget then becomes real and the heartbeat keeps stamping.

## F4 (High) — `environment` defaults to `development`, and three security guards key off it

**Where:** `api/app/config.py` — `environment: str = "development"`.

Three protections are conditioned on this one string:

- `_require_secrets_outside_development` — an empty `GITHUB_WEBHOOK_SECRET` makes
  `hmac.new(b"", body)` trivially forgeable; an empty `API_KEY` leaves the scan API open.
- `scans_router._start_local_scan` — 403 only outside development.
- `worker.ingest_codebase` — the same gate, second layer.

The validator itself is good work and correctly closes the empty-HMAC hole. The residual
defect is the default: the guard fires only if the operator remembers to set the very
variable that says "this is production". Forget `ENVIRONMENT=production` on a deploy and
you get, simultaneously, forgeable webhooks, an unauthenticated scan API, and
`POST /api/scans {"source":"local","path":"/"}` reading arbitrary host directories — and
nothing in the logs says the instance is unprotected.

**The fix.** Default `environment` to `"production"` and require opting *into*
development. Failing loudly on a fresh dev checkout is cheap; failing open on a
production deploy is not.

## F5 (Medium) — Rate limiting keyed on the proxy's IP

`api/app/api_security.py:rate_limit` uses `request.client.host`. Behind the fly.io proxy
that is the proxy's address for every caller, so the per-IP bucket becomes one global
60/min bucket: every user shares one limit and any single caller can exhaust it for
everyone. Read the platform's forwarded-client header (`Fly-Client-IP`) and trust it only
because the proxy is the sole ingress. Also note `count` is read after the `try`, so an
`expire` failure skips the limit check for that request — harmless, but worth tightening
while in there.

## F6 (Low) — The delivery GUID is consumed before the job is enqueued

`api/app/main.py` calls `already_seen()` (SET NX) *before* `json.loads` and before
`enqueue_webhook_delivery`. Any failure between them burns the GUID; GitHub's retry of
that same delivery gets `200 {"status":"duplicate"}` and the PR is never analyzed, with
no error anywhere. Enqueue first, or mark seen only after the `lpush` returns.

## CLOSED — verified correct, recorded so they are not "simplified" later

- **Empty webhook secret** — closed by `_require_secrets_outside_development`.
- **Zip bomb via declared size** — `_read_entry_capped` streams and counts *real*
  decompressed bytes rather than trusting `info.file_size`.
- **Zip-slip** — entries are never written to disk; absolute/`..` names rejected on the
  raw name, before prefix stripping.
- **Clone SSRF** — https-only, host allowlist, credentials rejected, and
  `-c http.followRedirects=false` so an allowlisted host cannot redirect elsewhere.
- **Registry outage → false block** — `Existence.UNKNOWN` maps to a non-block-eligible
  advisory. The promise holds.
- **Private-index 404** — `has_pip_extra_index` / `npmrc_private_scopes` correctly refuse
  to treat a public 404 as proof.
- **Coverage vs cleanliness** — `analytics.clean` derives from the coverage rollup, not
  `len(findings) == 0`. This is the right design, which is exactly why F1 matters.
- **Injection surface** — no raw SQL, no `eval`/`exec`/`pickle`/`yaml.load` in
  application code, no `dangerouslySetInnerHTML` in the dashboard.
- **Secret-pattern ReDoS** — checked; all patterns linear.
- **Committed private key** — the `.pem` at the repo root is untracked and matched by
  `.gitignore`; it has never been in git history.

## ACCEPT

- `source=local` in development is a deliberate dev affordance, double-gated. It becomes
  safe-by-default once F4 lands.
- `registries.check_exists` sleeps once after its final attempt before returning UNKNOWN.
  Costs 1.5s on a dead registry. Not worth a change.
